# Aqua Essence Development Guidance

Use the tracked project documentation as the source of truth:

1. `docs/development.md` — setup, verification, ownership, engineering rules,
   and private-data handling.
2. `docs/architecture.md` — component, process, persistence, and security
   boundaries.
3. `docs/matching-process-rules-and-guidelines.md` — domain policy and hard
   constraints.
4. `CONTRIBUTING.md` and `SECURITY.md` — change and reporting workflow.

Do not duplicate architecture snapshots or task backlogs in this file. If the
implementation changes, update the authoritative document and its tests.
